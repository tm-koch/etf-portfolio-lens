## Why

The corrected Amundi product page now identifies the right fund, but the ingestion pipeline still treats that page as a static download source. Its full-holdings control is generated by the Amundi web application, so live ingestion cannot currently obtain the complete XLSX workbook and falls back to parsing the page response incorrectly.

## What Changes

- Add an Amundi-specific full-holdings fetch strategy that calls the product API used by the canonical page and consumes its complete `compositionData` collection.
- Support any required Amundi product API, page context, or generated-download request needed for the Swiss professional English product context.
- Validate that the returned API data contains the complete holdings set, not the top-ten breakdown or an HTML response.
- Validate the API weight representation against the attached full XLSX fixture and retain `amundi_landing_xlsx_v1` weight semantics.
- Fail the ingestion run explicitly when the result is partial, non-XLSX, or structurally incompatible instead of generating a partial snapshot.
- Add a provider-specific fetch strategy field separate from `parser_id`, for example `fetcher_id: "amundi_product_page_v1"`.
- Preserve existing static fixture ingestion and historical snapshots.

## Capabilities

### New Capabilities

- `amundi-full-holdings-download`: Resolve, validate, and retrieve the complete Amundi holdings workbook for live ingestion.

### Modified Capabilities

- `etf-registry-metadata`: Extend Amundi registry entries with an explicit download strategy while preserving parser selection and canonical identity metadata.

## Impact

- `etf_ingestion_backend/fetching.py`: Add Amundi-specific resolution and response validation.
- `etf_ingestion_backend/pipeline.py` and models: Select a fetch strategy independently from the parser.
- `data/etf_registry.json`: Add the Amundi fetch strategy metadata.
- `tests/`: Add recorded request/response or workbook fixtures for full-holdings validation and failure cases.
- No change to frontend behavior or historical snapshots.
