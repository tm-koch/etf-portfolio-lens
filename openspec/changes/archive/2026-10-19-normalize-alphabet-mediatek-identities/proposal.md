# Proposal

## Why

Normalized ETF snapshots can present Alphabet's Class A and Class C shares as separate companies, fragmenting issuer-level views. MediaTek's current Chinese canonical name is less useful as the displayed name for the English-language interface.

## What Changes

- Add verified, exact-ISIN overrides that assign Alphabet Class A and Class C the same `company_id` and canonical name, `Alphabet Inc`, while retaining each instrument's own ISIN, ticker, and exposure.
- Add a verified, exact-ISIN override that displays `聯發科技股份有限公司` as `MediaTek Inc.` in normalized snapshots while preserving the actual provider source fields verbatim.
- Preserve provider source fields and leave downloaded source files unchanged; regenerate only normalized snapshots through the existing ingestion workflow.
- Add focused coverage for the shared Alphabet company identity, distinct instrument identities, and MediaTek's canonical display name with its original provider label retained in provenance.
- Confirm the exact ISIN selectors from the relevant provider rows before adding the mappings; those holdings are not present in the checked-in sample snapshots.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. Existing `security-identity-enrichment` and `etf-holdings-ingestion` requirements already cover canonical company identity, exact-ISIN overrides, distinct share-class instruments, and preservation of provider fields. This is a data-mapping change, so the change opts out of a redundant spec delta with `skip_specs: true`.

## Impact

- `data/security_overrides.json` for the identity and canonical-name mappings.
- Normalized snapshots generated by `etf_ingestion_backend`; downloaded provider files remain untouched.
- Focused ingestion tests for override selection and snapshot provenance.
